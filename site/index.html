Project 3 of 3 · cloud and backend engineering portfolio

Know when your services misbehave, and what happened.

CloudPulse checks HTTP services on a schedule, keeps their history, measures availability and latency, evaluates alert rules, and manages the incidents that follow: all in one FastAPI, PostgreSQL and React system that runs with a single Docker Compose command.

Real screenshots of the React dashboard talking to the real API. Availability is calculated from the checks that ran and is labelled that way; gaps in a chart mean "no checks", never downtime.

What it does

  • Scheduled checks

    A dedicated worker claims due resources with PostgreSQL leases, so a check never runs twice and a crash is recovered when the lease expires.

  • History and metrics

    Every accepted check is stored atomically with the latest state. Availability, p50/p95 latency and time-bucketed series are served by the API; retention is automatic.

  • Alerting

    Rules are evaluated in the same transaction as the check, with persisted counters, so a restart never loses progress or double-fires.

  • Incident management

    One incident per problem, acknowledgement by hand, automatic resolution on recovery, and a timeline that survives deleting the resource.

  • Safe by default

    An SSRF guard blocks private and metadata addresses, TLS is verified, URLs' query strings are never logged or displayed, and the app binds to loopback.

  • Operable

    Health and readiness probes, JSON logs, a hardened Compose profile, tested backup and restore, and CI that runs the whole system in a browser.

Quality and delivery

  • 764backend tests, including PostgreSQL integration tests
  • 218frontend component and contract tests
  • 30browser tests against the full Docker stack
  • 3 + 1CI jobs on free runners: backend, frontend, stack, hardened stack

Every push runs linting, type checks, the test suites, a full-stack smoke test of the check, alert, incident and recovery loop, and browser tests that add a service, break it, acknowledge the incident, fix it and delete it. A separate job brings up the hardened stack and verifies that a database backup restores into a disposable database.

Run the real thing

You need Git and Docker. The first command creates a .env with a generated database password. 

git clone https://github.com/gladwynL/CloudPulse.git
cd CloudPulse
python scripts/init_env.py
docker compose up --build --detach --wait
# dashboard: http://localhost:3000

The README covers the demo target, the hardened profile, backup and restore, and the tests. The project is local-first by design: it has no authentication, so a public cloud deployment is documented as a future design and has deliberately not been done.
